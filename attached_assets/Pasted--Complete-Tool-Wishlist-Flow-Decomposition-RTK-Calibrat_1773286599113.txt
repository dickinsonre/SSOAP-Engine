# Complete Tool Wishlist: Flow Decomposition & RTK Calibration

## The Full Decomposition Pipeline

```
Monitored Flow (Q_total)
│
├─── Phase 1: Import & QA/QC
│
├─── Phase 2: Dry/Wet Classification
│
├─── Phase 3: DWF Decomposition
│    │
│    ├── Q_gwi    (Groundwater Infiltration)
│    ├── Q_bsf    (Base Sanitary Flow)
│    └── Q_pattern (Diurnal Pattern × Q_bsf)
│    │
│    └── Q_dwf = Q_gwi + Q_bsf × Pattern(t)
│
├─── Phase 4: RDII Extraction
│    │
│    └── Q_rdii(t) = Q_total(t) − Q_dwf(t)
│
├─── Phase 5: RTK Calibration
│    │
│    ├── Solve-Once (direct)
│    └── Optimization (GA, DE, NM...)
│    │
│    └── Q_rdii_model = Σ UH_i(R_i, T_i, K_i) * Rainfall
│
└─── Phase 6: Validation & Export
```

### Tool 1.3 — Gap Detection & Filling

```
Algorithm Options:
├── Detection
│   ├── Missing timestamps (gaps > expected timestep)
│   ├── Flat-line detection (constant value > N hours)
│   ├── Stuck sensor (zero flow for unreasonable duration)
│   └── Transmission dropouts (regular periodic gaps)
│
├── Filling Methods
│   ├── Linear interpolation (short gaps < 2 hours)
│   ├── Spline interpolation (medium gaps 2-12 hours)
│   ├── Pattern-based fill (use DWF pattern for gaps during dry weather)
│   ├── Neighbor gage substitution (rainfall)
│   └── Flag-only (mark gaps, don't fill)
│
└── Parameters
    ├── max_gap_to_fill: duration (default: 4 hours)
    ├── flatline_threshold: hours (default: 6)
    ├── zero_flow_threshold: hours (default: 2)
    └── interpolation_method: enum [linear, spline, pattern, none]
```

### Tool 1.4 — Outlier Detection & Removal

```
Methods:
├── Statistical
│   ├── Z-score (|z| > 3.0)
│   ├── Modified Z-score (MAD-based, robust to skew)
│   ├── IQR fence (Q1 - 1.5×IQR, Q3 + 1.5×IQR)
│   └── Grubbs test (single outlier)
│
├── Physical
│   ├── Negative flow check
│   ├── Maximum physically possible flow (from pipe capacity)
│   ├── Maximum rate of change (dQ/dt threshold)
│   └── Depth-velocity consistency (Q = V × A check)
│
├── Contextual
│   ├── Flow without rainfall outside DWF envelope
│   ├── No flow during expected peak hours
│   └── Rainfall without flow response
│
└── Parameters
    ├── z_score_threshold: float (default: 3.0)
    ├── iqr_multiplier: float (default: 1.5)
    ├── max_flow: float (pipe full capacity)
    ├── max_dq_dt: float (max rate of change, CFS/min)
    └── action: enum [flag, remove, replace_interpolate]
```

### Tool 2.3 — RDII Influence Period Detector

```
Purpose: Determine when RDII response starts and ends for each event

Method:
├── Start: Flow exceeds DWF envelope by threshold amount
├── End: Flow returns to within DWF envelope
│
├── Alternative methods:
│   ├── Slope-based: detect inflection point in rising limb
│   ├── Statistical: flow > DWF_mean + N × DWF_stddev
│   ├── Pattern-based: deviation from expected DWF pattern > threshold
│   └── Manual: user clicks start/end on hydrograph
│
└── Parameters
    ├── rise_threshold: float (% above DWF, default: 10%)
    ├── recession_threshold: float (% above DWF, default: 5%)
    ├── min_rdii_duration: hours (default: 2)
    ├── max_rdii_duration: hours (default: 168 = 7 days)
    └── method: enum [envelope, slope, statistical, manual]
```

### Tool 2.4 — Antecedent Moisture Tracker

```
Purpose: Track soil moisture state to improve RDII prediction

Methods:
├── API (Antecedent Precipitation Index)
│   ├── API(t) = k × API(t-1) + P(t)
│   ├── k = decay coefficient (0.85 - 0.98)
│   └── Classify: dry (API < 0.5"), moderate (0.5-1.5"), wet (> 1.5")
│
├── 5-Day Antecedent Rainfall
│   └── Simple sum of rainfall in preceding 5 days
│
├── SCS Antecedent Moisture Condition (AMC)
│   ├── AMC I:  < 0.5" in preceding 5 days (dry)
│   ├── AMC II: 0.5-1.1" (average)
│   └── AMC III: > 1.1" (wet)
│
└── Parameters
    ├── method: enum [API, 5day, AMC]
    ├── decay_factor: float (for API, default: 0.90)
    ├── lookback_days: int (for 5-day method, default: 5)
    └── output: time series of moisture index
```

### Tool 3.2 — GWI Seasonal Model

```
Purpose: Model GWI variation across seasons

Methods:
├── Constant GWI
│   └── Single value from MNF analysis (simplest)
│
├── Monthly GWI
│   └── Different GWI for each month (from monthly MNF)
│
├── Sinusoidal Model
│   ├── GWI(t) = GWI_mean + A × sin(2π(t - φ)/365)
│   ├── A = seasonal amplitude
│   └── φ = phase shift (day of peak GWI)
│
├── Regression on Water Table
│   ├── GWI(t) = a + b × WaterTable(t)
│   └── Requires nearby USGS groundwater well data
│
└── Parameters
    ├── model_type: enum [constant, monthly, sinusoidal, regression]
    ├── gwi_mean: float (from MNF analysis)
    ├── amplitude: float (sinusoidal only)
    ├── phase_day: int (sinusoidal only, day of year for peak)
    └── water_table_data: optional time series
```

### Tool 3.3 — Base Sanitary Flow (BSF) Calculator

```
Purpose: Determine the non-GWI component of dry weather base flow

Calculation:
  BSF = Average_DWF − GWI

Methods:
├── Per-Capita Method
│   ├── BSF = Population × GPCD (gallons per capita per day)
│   ├── GPCD typically 60-120 gpd/capita
│   └── Requires population estimate for sewershed
│
├── Direct Measurement
│   ├── BSF = Mean_DWF − GWI
│   └── Uses dry day average minus GWI estimate
│
├── Billing Data Method
│   ├── BSF = (Water_Billed × Return_Factor)
│   ├── Return factor typically 0.7-0.9
│   └── Requires water billing records
│
└── Parameters
    ├── method: enum [per_capita, direct, billing]
    ├── population: int (for per_capita)
    ├── gpcd: float (default: 80 gpd/capita)
    ├── return_factor: float (for billing, default: 0.85)
    ├── commercial_flow: float (additional non-residential base flow)
    └── industrial_flow: float (additional industrial base flow)

Output:
├── BSF value (flow units per day)
├── BSF as fraction of total DWF
├── BSF + GWI = total average DWF (verification)
└── Per-capita comparison to typical ranges
```

### Tool 3.5 — DWF Reconstruction Engine

```
Purpose: Reconstruct complete DWF time series for entire monitoring period

Formula:
  Q_dwf(t) = GWI(t) + BSF × Pattern(hour, daytype)

Where:
├── GWI(t) = groundwater infiltration (constant or seasonal)
├── BSF = base sanitary flow (MGD or CFS)
├── Pattern(hour, daytype) = diurnal multiplier
```

## Phase 5: RTK Calibration (10 Tools)

### Tool 5.1 — RTK Parameter Definition

```
SWMM5 RTK Unit Hydrograph Parameters:

Each hydrograph set has 3 triangular unit hydrographs:
UH1 = Fast response  (direct inflow: roof drains, manhole covers)
UH2 = Medium response (defect infiltration: cracked pipes, bad joints)
UH3 = Slow response   (groundwater: high water table seepage)

Parameters per UH:
├── R = fraction of rainfall volume entering sewer (dimensionless, 0-1)
├── T = time to peak of unit hydrograph (hours)
├── K = ratio of recession limb time to time to peak (dimensionless, >1)
└── Ia = initial abstraction (inches or mm, optional, per UH set)

Total parameters: 9 core (R1,T1,K1, R2,T2,K2, R3,T3,K3)
                + 1 optional (Ia)
                = 10 per sewershed per month/season

Full SWMM5 RDII definition:
├── 12 months × 3 UH × 3 params = 108 parameters (maximum)
├── Seasonal groups (e.g., 4 seasons × 9 = 36 parameters)
└── Single set: 9 parameters (minimum, most common for calibration)
```

### Tool 5.3 — Solve-Once (Direct Calculation)

```
Purpose: Calculate RTK parameters directly from observed RDII hydrograph
         shape without iterative optimization. Fast, deterministic, gives
         a good starting point.

Methods:

Method A — Peak Decomposition
├── Find the first distinct peak → sets T1
├── Find the second peak or inflection → sets T2
├── Fit exponential to recession tail → sets T3, K3
├── Allocate volume: area under each sub-hydrograph → R1, R2, R3
├── K1, K2 from width of each peak at half-height
└── Pro: Fast. Con: Requires distinct peaks.

Method B — Moment Matching
├── Compute moments of observed RDII hydrograph:
│   ├── M0 = total volume → R_total
│   ├── M1 = centroid time → weighted average of T values
│   └── M2 = variance → spread of responses
├── Allocate across 3 UHs using assumed proportions
├── Solve T and K from moment equations
└── Pro: Works for any shape. Con: Non-unique solution.

Method C — Exponential Decomposition
├── Fit sum of 3 exponentials to recession limb:
│   Q(t) = A1×exp(-t/τ1) + A2×exp(-t/τ2) + A3×exp(-t/τ3)
├── Convert time constants τ to T and K:
│   T_i ≈ τ_i / K_i, where K_i estimated from shape
├── Convert amplitudes A to R values:
│   R_i = A_i × (T_i × (1+K_i)) / (2 × rainfall_depth × area)
└── Pro: Robust. Con: Sensitive to recession start point.

Method D — Template Library
├── Use typical RTK values for similar sewersheds as starting point
├── Scale R-values to match observed total R-value
├── Adjust T-values to match observed time to peak
├── Library entries based on:
│   ├── Pipe material (VCP, PVC, concrete, brick)
│   ├── Pipe age (new, 20yr, 40yr, 60yr+)
│   ├── Soil type (sand, silt, clay)
│   └── Sewer type (separate, partially combined)
└── Pro: Works with minimal data. Con: Generic.

Output:
├── Initial RTK parameter set: (R1,T1,K1, R2,T2,K2, R3,T3,K3, Ia)
├── Predicted RDII hydrograph from these parameters
├── Overlay on observed RDII
├── Goodness-of-fit metrics (see Tool 5.6)
└── "Use as starting point for optimization" button
```

**All fit metrics:**
| Metric | Formula | Perfect | Acceptable |
|---|---|---|---|
| NSE | 1 − Σ(Qobs-Qsim)² / Σ(Qobs-Q̄obs)² | 1.0 | > 0.65 |
| KGE | 1 − √[(r-1)² + (β-1)² + (γ-1)²] | 1.0 | > 0.50 |
| R² | [Σ(Qobs-Q̄)(Qsim-Q̄)]² / [Σ(Qobs-Q̄)² × Σ(Qsim-Q̄)²] | 1.0 | > 0.70 |
| RMSE | √[Σ(Qobs-Qsim)² / N] | 0.0 | < 15% of mean |
| PBIAS | 100 × Σ(Qsim-Qobs) / Σ(Qobs) | 0.0% | ±15% |
| Peak Error | (Qpeak_sim − Qpeak_obs) / Qpeak_obs × 100 | 0.0% | ±20% |
| Volume Error | (Vol_sim − Vol_obs) / Vol_obs × 100 | 0.0% | ±15% |
| MAE | Σ | Qobs-Qsim | / N | 0.0 | context-dependent |
| d (index of agreement) | 1 − Σ(Qobs-Qsim)² / Σ( | Qsim-Q̄ | + | Qobs-Q̄ | )² | 1.0 | > 0.80 |

### Tool 5.8 — Multi-Event Calibration Manager

```
Purpose: Calibrate one RTK set against multiple storm events simultaneously

Strategy Options:
├── Option A: Combined Objective
│   ├── Minimize: Σ_events [ w_i × ObjectiveFunction(event_i) ]
│   ├── Weight events by: equal, by volume, by peak, by importance
│   └── Single optimization → single RTK set
│
├── Option B: Per-Event → Average
│   ├── Optimize each event independently → get N RTK sets
│   ├── Average parameters (mean, median, or weighted)
│   ├── Report parameter variability across events
│   └── Good for understanding which events are consistent
│
├── Option C: Sequential Refinement
│   ├── Calibrate on largest event first
│   ├── Use result as starting point for next event
│   ├── Iterate until parameters stabilize
│   └── Weight toward events with better data quality
│
└── Option D: Split Sample
    ├── Calibrate on subset of events
    ├── Validate on held-out events
    ├── Report calibration vs validation fit
    └── Best practice for predictive confidence

Parameters:
├── strategy: enum [combined, per_event_average, sequential, split_sample]
├── event_weights: float[] (per event weight, sum to 1)
├── calibration_events: list (for split sample)
├── validation_events: list (for split sample)
└── convergence_tolerance: float (default: 0.001)
```

### Tool 5.10 — Parameter Sensitivity Analysis

```
Purpose: Understand which RTK parameters have the most influence
         on model output, guiding calibration effort

Methods:
├── One-at-a-Time (OAT)
│   ├── Vary each parameter ±20% while holding others fixed
│   ├── Plot: parameter value vs objective function
│   └── Identifies individual parameter influence
│
├── Morris Method (Elementary Effects)
│   ├── Efficient global screening method
│   ├── Ranks parameters by importance
│   └── Identifies interactions
│
├── Sobol Sensitivity Indices
│   ├── Variance-based global sensitivity
│   ├── First-order indices (individual effects)
│   ├── Total-order indices (including interactions)
│   └── Requires more model evaluations
│
└── Output:
    ├── Tornado diagram (parameter ranking by influence)
    ├── Spider plot (normalized sensitivity)
    ├── Interaction heatmap (which params interact)
    └── Recommendation: "Focus calibration effort on R1, T1, R2"
```
